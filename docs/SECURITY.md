# Security

Treat the gateway as potentially compromised. It can consume allowed GPU services and see the data sent through them. It must not select arbitrary LAN hosts, reach administration paths, supply upstream credentials, run commands or change configuration. Local route profiles, strict path/header checks, body/concurrency/rate/idle limits and restricted dialers form the application boundary. systemd adds an unprivileged account, empty capabilities, filesystem restrictions and default-deny IP egress. The optional health listener is off by default and must bind localhost.

A network attacker must pass ordinary TLS verification and the nonce-bound Ed25519 server signature. Obtain the public key and key ID directly from the server operator through an authenticated independent channel, compare its fingerprint, then configure `server_keys`. No production key is embedded. For rotation, install both independently verified old/new public keys, reload, switch the server, then remove the old key. Never use a key learned only from the same unauthenticated connection being verified. A customer-operated TLS inspection proxy can observe or alter traffic; signature verification authenticates the server handshake, not secrecy from that proxy.

The local token is a bearer credential. Store token and file-backed upstream secrets as root-owned 0600/0640 files with only the service group permitted to read them. Configuration is local; the cloud cannot push updates. Updates are explicitly installed by the operator. Verify signed checksums and review SBOM/vulnerability results before upgrading.

Audit JSON lines record timestamp, session, route, method, path, status, input/output byte counts, duration, upstream and request ID. They intentionally omit prompts, outputs and secret headers. Review unexpected denied paths, excessive usage and reconnect/signature failures through the service journal and audit file. Request metadata remains sensitive; restrict and rotate logs.

The process-level policy and container sandbox do not replace an OS egress boundary. IP filtering must be tested on the deployment kernel; systemd IP restrictions are IP-based, while the application also limits ports. Compromise of an allowlisted upstream service and malicious content generated by a model require separate controls. The standalone test gateway is a loopback development harness, not production tenancy, token revocation or metering infrastructure.

Report suspected vulnerabilities privately to the repository maintainers through GitHub private vulnerability reporting, if enabled. If unavailable, request a private contact through the repository without posting exploit details, tokens or customer data publicly. No dedicated security mailbox has been supplied.

Allowed request bodies can still contain remote resources such as `image_url`, document URLs or converter directives. The connector does not understand every upstream body schema and cannot prevent an allowed model/converter server from fetching those URLs. Sandbox and restrict egress on the upstream servers themselves, and disable remote fetch functionality where possible. Local connector method/path restrictions alone do not prevent upstream-induced SSRF.

Public contributions must use synthetic test data and documentation addresses. Keep customer configurations, captured traffic, internal rollout plans and credentials out of commits. Local environment files and key material are ignored; CI scans Git content for secrets. Secret scanning complements manual review of customer and infrastructure information.
